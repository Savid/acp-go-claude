Each [ACP session](https://agentclientprotocol.com/protocol/session-setup) maps
to a [Claude Code session](https://code.claude.com/docs/en/sessions) and
process. Claude persists native session transcripts as JSONL under its config
directory, and the adapter can also mirror/import those rows through a
[SessionStore](/docs/features/session-store).

Sessions behave the same in [standalone CLI and embedded Go](/docs/get-started/run-modes).
Configuration happens before the ACP `session/*` methods arrive; use
[CLI reference](/docs/reference/cli) for flags and
[Go API](/docs/reference/go-api) for embedded options.

## Create

ACP [`session/new`](https://agentclientprotocol.com/protocol/session-setup)
starts a fresh Claude session with:

- absolute `cwd`
- optional `additionalDirectories`
- optional MCP servers
- optional `_meta.claude.options`
- optional `_meta.claude.goal`
- optional raw-message emission settings

The response includes `sessionId`, [modes](https://agentclientprotocol.com/protocol/session-modes),
model state, [config options](https://agentclientprotocol.com/protocol/session-config-options),
and Claude-specific [`_meta.claude`](/docs/reference/meta) model variant
metadata and goal state.

## Prompt

ACP [`session/prompt`](https://agentclientprotocol.com/protocol/prompt-turn)
sends one turn to Claude. Prompts are queued per session: if a turn is already
active, the next prompt waits for the turn semaphore.

The response includes stop reason, [usage](https://agentclientprotocol.com/rfds/session-usage)
when available, and the user message ID supplied by the client.

## Subagents

Claude [subagents](https://code.claude.com/docs/en/sub-agents) run inside the
same Claude session from the ACP client's point of view. They do not create a
second ACP session. Clients see the resulting tool calls, tool updates,
messages, plan updates, and usage through the normal prompt stream.

When a configured [SessionStore](/docs/features/session-store) supports
subkeys, the adapter can materialize subagent transcript files during
store-backed resume so Claude can continue a restored session with its related
native context.

## Cancel

`session/cancel` interrupts the active Claude turn with the Claude control
protocol. It also cancels outstanding ACP
[permission requests](/docs/features/permissions) tied to that turn. A
cancelled prompt returns `cancelled`.

## Close

`session/close` closes the Claude process and associated MCP bridge,
materialized temp config, and active turn resources. `Agent.Close` closes all
sessions.

## List

ACP [`session/list`](https://agentclientprotocol.com/protocol/session-list)
discovers local Claude transcripts for the requested `cwd`. When a configured
`SessionStore` implements `SessionStoreLister`, list results also include
store-backed sessions for the same Claude project key.

Results are cursor-paginated with a page size of 50.

## Load vs resume

| Method | Behavior |
| --- | --- |
| [`session/load`](https://agentclientprotocol.com/rfds/session-resume) | Starts or reuses the session and replays saved transcript updates to the ACP client before returning. |
| [`session/resume`](https://agentclientprotocol.com/rfds/session-resume) | Starts or reuses the session without replaying history. |

Both methods can hydrate missing local Claude JSONL from a configured
`SessionStore`. Remote upload uses the Claude-specific
[session import](/docs/reference/session-import) extension.

If a matching session is already active, both methods reuse it instead of
launching another Claude process. The match includes `cwd`, additional
directories, MCP configuration, Claude options, and raw-message settings.

## Goals

Claude-specific [goal metadata](/docs/features/goals) is session state. Clients
can set or clear `_meta.claude.goal` at session start or with the
`_claude/session/setGoal` extension method. Goal-only updates are emitted
through `session_info_update._meta.claude.goal` and do not bump the session
`updatedAt` timestamp.

The adapter also maps Claude-native `/goal` transcript mirror rows into the same
metadata shape when Claude emits them. Native goal extraction is independent of
whether an external `SessionStore` is configured.

## Fork

Unstable [`session/fork`](https://agentclientprotocol.com/rfds/session-fork)
starts Claude with `--resume <session-id>` and `--fork-session`, creates a new
ACP session ID, and copies session permission rules intentionally from the
source session.

<Note>
  Claude session IDs are UUID-shaped. Tool call IDs are passed through from
  Claude and are only required to be unique within the session.
</Note>
