title: "Authentication"
description: "How to supply Claude credentials, and how to broker a login over ACP"
---

The adapter does not manage Claude Code account state. Authentication is owned by
the local Claude Code installation selected by `-home` (`WithHome`), so there is
nothing for a host to log into through ACP.

## No ACP auth methods

ACP initialize reports an empty `authMethods` list. A host never calls
`authenticate` against this adapter, and ACP `logout` clears only
adapter-owned session state — it never touches Claude account material. An
authentication problem inside Claude surfaces as an ordinary turn failure with
cause `provider`, not as an ACP auth challenge; see
[ACP methods](/docs/reference/acp-methods).

## Supplying credentials

Point the adapter at an already-authenticated Claude config directory with
`-home` (`WithHome`), or pass Claude environment variables for automation and
tests:

```go
err := claudeacp.Serve(ctx, input, output,
	claudeacp.WithHome("/tmp/claude-home"),
	claudeacp.WithEnv(map[string]string{
		"ANTHROPIC_API_KEY": "sk-...",
	}),
)
```

Environment variables set with `WithEnv` (or in `ProcessIsolation.BaseEnvironment`)
are merged into every launched Claude process. Keep secrets in
the environment rather than in seeded config files. See
[Models and config](/docs/features/models-config) for pointing Claude at a
custom Anthropic-compatible endpoint.

## Token auth and usage reporting

Claude Code reads subscription usage only for an OAuth session it recognises: a
config directory logged in through `claude login`, or a
`CLAUDE_CODE_OAUTH_TOKEN`. A directory authenticated solely by
`ANTHROPIC_AUTH_TOKEN` runs prompts normally but reports no usage, so the
harness prints no windows and emits no rate-limit events.

To keep [`_claude/rateLimits`](/docs/reference/acp-methods) useful under token
auth, the adapter falls back to reading usage from the Anthropic API directly.
Tokens minted by `claude setup-token` are inference-only, so that fallback may
have to spend a one-token inference request to read the rate-limit response
headers. Disable it with `WithClaudeDirectAPI(false)`.

## Brokering a login over ACP

A host that runs a worker with no credential of its own can offer exactly three
Claude authentication methods through `_claude/auth/*`: native
`claude auth login`, a token generated by `claude setup-token`, and an
Anthropic Console API key. Native login remains in Claude's own credential
store. The two secret methods reach the host through a one-shot `credential`
harvest and return to a session only through typed environment injection.
Neither method runs a setup command or writes a credential file.

The provider-auth surface is absent when a Claude cloud selector, bearer
credential, `apiKeyHelper`, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, or
`CLAUDE_CODE_OAUTH_TOKEN` is configured. Those
variables override a login stored in the config directory, so offering a
durable connection beside one would advertise a credential the agent cannot
use. It is also absent in bare mode and when agent-wide user, managed, seeded,
or overlay settings configure one of those variables or `apiKeyHelper`.

| Option | Effect |
| --- | --- |
| `WithProviderAuthRoot(path)` | Absolute, durable, host-owned directory holding the values-free ledger. Required: unset, relative, unusable, bare mode, or agent-wide static authentication leaves every method unadvertised and answering method-not-found. |
| `WithProviderAuthDirectHome(path)` | Consent gate for disconnecting the native-login method. Must resolve to the same directory as `WithHome`; secret-backed disconnect does not touch the native home. |

```go
err := claudeacp.Serve(ctx, input, output,
	claudeacp.WithHome("/var/lib/worker/claude-home"),
	claudeacp.WithProviderAuthRoot("/var/lib/worker/provider-auth"),
	claudeacp.WithProviderAuthDirectHome("/var/lib/worker/claude-home"),
)
```

Both sides of the consent gate are resolved when the agent starts, and every
native call this surface makes runs against the directory that resolution found.
`disconnect` clears an account and its platform keystore items and cannot be
undone, so it first checks that the configured path still names that same
directory; a path repointed while the agent runs answers `policy` and removes
nothing.

The flow is `_claude/auth/methods` → `_claude/auth/authorize` →
`_claude/auth/callback` → `_claude/auth/status`, with `_claude/auth/cancel` to
abandon it and `_claude/auth/inventory` to ask what is resident after a restart.
The catalog is one provider (`anthropic`) with `login`, `setup-token`, and
`api-key`. `login` returns `interaction: "callback"` and a `claude.com` URL.
The two API methods return `interaction: "secret"`; setup-token also tells the
operator to run `claude setup-token` and paste the generated token. A successful
secret callback reports `saved`, never `authenticated`. Harvest succeeds once,
scrubs the flow-held bytes immediately, and emits only `api` with metadata
`env: "CLAUDE_CODE_OAUTH_TOKEN"` or `env: "ANTHROPIC_API_KEY"`.

`callback` waits for the login child to exit naturally, then requires a zero
exit and a native account reading that advanced past the one captured before
the flow. An unchanged logged-in account is reported as acceptance-unknown
rather than attributed to this flow. A nonzero exit, internal timeout, or
incomplete containment fence never authenticates.
Cancellation of the request carrying the pasted value does not cancel the
flow; `_claude/auth/cancel`, supersession, session close, and flow expiry own
that lifecycle. When the browser completes through Claude's loopback hook and no callback arrives,
`status` additionally requires the account reading to differ from the one taken
before the flow started.

<Warning>
The pasted value is `<code>#<state>`, not the code on its own — submitting only
the first half cannot complete the login. `cancel` fences the adapter's own
login process and never claims the authorization was revoked at Anthropic.
</Warning>

`authorizeRequestId` is the caller-minted idempotency key for one
(`sessionId`, `providerId`) pair. A repeat of the newest key replays the same
presentation verbatim — no second login child, no native call — while a key a
later `authorize` replaced is refused with `-32602` naming
`authorizeRequestId`, because minting in its place would tear down the live
flow whose URL the operator is looking at.

`session/close` cancels every pending flow the session owns and kills its login
child, and the id then answers unknown-session on every `_claude/auth/*` method,
including an `authorize` that was already in flight. A `session/load`,
`session/resume`, or `session/fork` that rebuilds a session under that id serves
the surface again; only `session/delete` refuses it for good.

`disconnect` cancels every pending login on the config directory before it
clears the account, because the harness arms its loopback listener
unconditionally: a browser tab reaching a still-running login child installs a
credential with no method call driving it, and an absence proof taken beside one
would be true only for the instant it was read.

The login child opens no browser on the host. Its environment carries a
mode-`0700` directory of no-op launchers ahead of every other `PATH` entry and
points `BROWSER` inside it, so a harness that reads `BROWSER` and one that execs
`open` or `xdg-open` directly are both covered; the directory is removed when
the flow's fence closes the child. Windows admits no such containment — the
`start` that opens a URL is a `cmd.exe` builtin with no image to shadow, and the
system directory precedes every `PATH` entry — so `authorize` fails there rather
than opening a tab that could complete a grant unattended.

`inventory` reads the values-free ledger and checks the residence for the
recorded method. Native login probes `claude auth status`; setup tokens and API
keys compare the exact binding lineage injected into the session. It never
reads `.credentials.json`, whose presence proves nothing on macOS, where the
login Keychain is authoritative and that file is a fallback the composite store
leaves behind. Credentials the adapter did not establish write no ledger entry
and are invisible to `inventory`.
