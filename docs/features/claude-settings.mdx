The adapter reads a small, trusted subset of
[Claude settings](https://code.claude.com/docs/en/settings) before launching a
session. These values influence initial
[model/config state](/docs/features/models-config) and Claude process
environment.

## Configure Claude home

Standalone, through the [CLI](/docs/reference/cli):

```bash
go run ./cmd/acp-go-claude -claude-home /path/to/claude-home
```

Embedded, through the [Go API](/docs/reference/go-api):

```go
claudeacp.Serve(ctx, input, output,
    claudeacp.WithClaudeHome("/path/to/claude-home"),
)
```

## Files read by the adapter

Before launch, the adapter reads a small subset of settings itself, in order:

1. User settings from `CLAUDE_CONFIG_DIR/settings.json` or `~/.claude/settings.json`.
2. Project settings at `<cwd>/.claude/settings.json`.
3. Local project settings at `<cwd>/.claude/settings.local.json`.
4. Managed settings:
   - macOS: `/Library/Application Support/ClaudeCode/managed-settings.json`
   - Linux/Unix: `/etc/claude-code/managed-settings.json`
   - Windows: `C:\Program Files\ClaudeCode\managed-settings.json`

Later files can override scalar values. Available model lists are merged while
preserving order.

## Filesystem sources passed to Claude

Launched Claude sessions also receive
[`--setting-sources=user,project,local`](https://code.claude.com/docs/en/agent-sdk/claude-code-features)
by default. That lets the Claude CLI load normal Claude Code features such as
`CLAUDE.md`, `.claude/` skills, hooks, commands, and settings from those
sources.

Embedded callers can choose a narrower set:

```go
claudeacp.Serve(ctx, input, output,
    claudeacp.WithSettingSources(claudeacp.SettingSourceProject),
)
```

Or disable user/project/local filesystem sources entirely:

```go
claudeacp.Serve(ctx, input, output,
    claudeacp.WithSettingSources(),
)
```

MCP isolation is still enforced separately with Claude's
[`--strict-mcp-config`](https://code.claude.com/docs/en/cli-usage), so settings
sources do not merge extra user/project MCP servers into the ACP session.

## Supported fields

| Field | Used for |
| --- | --- |
| `model` | Initial model fallback. |
| `effortLevel` | Initial reasoning effort fallback. |
| `availableModels` | Model allowlist merged with `CLAUDE_MODEL_CONFIG`. |
| `permissions.defaultMode` | Initial [permission mode](https://code.claude.com/docs/en/permission-modes) fallback. |
| `env` | Additional Claude process environment. |

## Environment validation

Settings `env` keys must be uppercase-style variable names. These variables
combine with process env, [`WithEnv`](/docs/reference/go-api#claude-process),
and session [`_meta.claude.options.env`](/docs/reference/meta#session-options):

- uppercase letters
- underscores
- digits after the first character

Values must be non-empty strings without NUL bytes. Invalid keys are ignored
and debug-logged.

## Claude home

`-claude-home` and `WithClaudeHome` are canonicalized and must point at an
existing directory. The resulting path is used as `CLAUDE_CONFIG_DIR` for
launched sessions, with the filesystem trust boundary described in
[Security](/docs/operations/security).
