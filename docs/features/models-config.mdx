Model and configuration state comes from Claude initialize/settings metadata
when available, with conservative fallbacks when not. ACP exposes the portable
parts through [session modes](https://agentclientprotocol.com/protocol/session-modes)
and [session config options](https://agentclientprotocol.com/protocol/session-config-options).

## Model selection

Initial model selection honors both process defaults and per-session
[`_meta.claude.options`](/docs/reference/meta#session-options):

1. `_meta.claude.options.model`
2. `WithDefaultModel` or `-model`
3. `ANTHROPIC_MODEL`
4. Claude settings/default behavior

Standalone, through the [CLI](/docs/reference/cli):

```bash
go run ./cmd/acp-go-claude -model sonnet
```

Embedded, through the [Go API](/docs/reference/go-api):

```go
claudeacp.Serve(ctx, input, output,
    claudeacp.WithDefaultModel("sonnet"),
)
```

Clients should prefer ACP `session/set_config_option` with the `model` config
option for model changes. Unstable `session/set_model` is still implemented
for `github.com/coder/acp-go-sdk` compatibility; see
[ACP methods](/docs/reference/acp-methods) for the method list.

## `CLAUDE_MODEL_CONFIG`

Hosts can tune advertised model IDs with `CLAUDE_MODEL_CONFIG` JSON. It can be
provided as process env or [`WithEnv`](/docs/reference/go-api#claude-process):

```json
{
  "modelOverrides": {
    "opus": "claude-opus-4-7-20260101"
  },
  "availableModels": ["default", "sonnet", "opus"]
}
```

| Field | Purpose |
| --- | --- |
| `modelOverrides` | Map user-facing choices to Claude CLI model IDs. |
| `availableModels` | Restrict and order the model choices shown to clients. |

Trusted [Claude settings](/docs/features/claude-settings) can also provide
`availableModels`, which is merged with `CLAUDE_MODEL_CONFIG.availableModels`.
`modelOverrides` only comes from `CLAUDE_MODEL_CONFIG`.

Standalone CLI:

```bash
CLAUDE_MODEL_CONFIG='{"availableModels":["default","sonnet","opus"]}' \
  go run ./cmd/acp-go-claude
```

Embedded Go:

```go
claudeacp.Serve(ctx, input, output,
    claudeacp.WithEnv(map[string]string{
        "CLAUDE_MODEL_CONFIG": `{"availableModels":["default","sonnet","opus"]}`,
    }),
)
```

## Modes

ACP mode IDs map to
[Claude permission modes](https://code.claude.com/docs/en/permission-modes):

| ACP mode | Claude permission mode |
| --- | --- |
| `default` | normal permission prompts |
| `plan` | plan mode |
| `accept_edits` | `acceptEdits`, auto-accept edit tools |
| `bypass_permissions` | `bypassPermissions`, bypass Claude permission prompts |
| `auto` | Claude auto mode, only advertised for compatible models |
| `dont_ask` | `dontAsk`, reject permission prompts |

The same values are mirrored through a generic `mode` config option for clients
without native mode UI.

## Other config options

| Config ID | Type | Behavior |
| --- | --- | --- |
| `model` | select | Changes the active Claude model. |
| `mode` | select | Changes Claude permission mode. |
| `output_style` | select | Applies a [Claude output style](https://code.claude.com/docs/en/output-styles). |
| `effort` | select | Applies Claude reasoning effort when the model supports it. |
| `fast_mode` | boolean | Toggles Claude Fast Mode when reported by the CLI. |

`fast_mode` uses the ACP model-config RFD category `model_config`. `effort`
keeps the stable `thought_level` category for compatibility with current
clients.

Changing model can clamp mode and effort if the new model does not support the
current choices. The agent emits config/mode updates after changes; those
updates are listed in [Update mapping](/docs/reference/updates).

Known effort IDs are:

```text
low
medium
high
xhigh
max
```

The adapter only advertises the effort values Claude reports for the active
model. Clients should not assume every model supports every effort level.

Each model entry and model config value can also include per-model Claude
metadata:

```json
{
  "_meta": {
    "claude": {
      "supportedEffortLevels": ["low", "medium", "high", "xhigh", "max"],
      "supportsAutoMode": true,
      "contextWindow": 1000000
    }
  }
}
```

This lets clients render model-specific effort choices without hardcoding the
Claude model matrix. Missing keys mean the adapter does not know that capability
for that model.

## Claude model metadata

Session responses include Claude-specific
[`_meta.claude`](/docs/reference/meta):

```json
{
  "claude": {
    "modelId": "opus",
    "variant": "high",
    "availableVariants": ["low", "medium", "high"]
  }
}
```

This metadata is Claude-specific and should not be required for portable ACP
behavior.
