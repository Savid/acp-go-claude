This tutorial takes you from nothing to a streamed assistant reply over ACP.

## Prerequisites

- A local Claude Code CLI (`claude`) on `PATH`, **version 2.0.0 or newer** and
  already authenticated. The adapter probes the CLI version at session start and
  fails fast on anything older.
- A Go toolchain to build and run the example clients.

## Steps

<Steps>
  <Step title="Clone the repository">
    The example programs are repo-relative (`go run ./examples/...`), so start
    from a checkout:

    ```sh
    git clone https://github.com/savid/acp-go-claude && cd acp-go-claude
    ```
  </Step>
  <Step title="Run a single-prompt turn">
    The minimal client starts the adapter, initializes, opens a session, sends
    one prompt, and prints the streamed reply:

    ```sh
    go run ./examples/minimal-client "Reply with hello from ACP"
    ```
  </Step>
  <Step title="Try an interactive session">
    The interactive client keeps a session open so you can send several prompts:

    ```sh
    go run ./examples/interactive-chat
    ```
  </Step>
</Steps>

## Verify

The example prints the streamed assistant reply to stdout and exits `0`. A
greeting line derived from your prompt confirms the full path worked: agent
initialization, session creation, the prompt turn, and streamed output back
through ACP.

If you instead launch the raw command for an ACP host to drive, it blocks on
stdin waiting for JSON-RPC frames and writes ACP frames only to stdout; add
`-debug` to send diagnostics to stderr:

```sh
go run ./cmd/acp-go-claude -path "$(command -v claude)" -home /tmp/claude-home -debug
```
