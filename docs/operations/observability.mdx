Export Claude Code and adapter telemetry to any OpenTelemetry backend that
accepts OTLP, such as Grafana, Honeycomb, Datadog, Langfuse, or a local
collector.

This adapter has two telemetry layers:

- [Claude Code telemetry](https://code.claude.com/docs/en/agent-sdk/observability)
  from the `claude` CLI process.
- Adapter telemetry from ACP methods, [sessions](/docs/core/sessions),
  [permissions](/docs/features/permissions), [elicitation](/docs/features/elicitation),
  [MCP bridge](/docs/features/mcp), and
  [session-store](/docs/features/session-store) work.

## How telemetry flows

Claude Code has its own OpenTelemetry instrumentation. It records model
requests, tool execution, hook execution, usage, cost, and Claude-native log
events. The adapter passes environment variables into the Claude process, and
Claude exports directly to your collector.

The adapter also emits telemetry for the ACP boundary that Claude cannot see:

- ACP method latency and errors
- prompt turns and cancellation
- permission and elicitation callbacks
- ACP-transport MCP bridge operations
- session-store load, append, list, materialize, and delete operations
- [raw Claude message](/docs/features/raw-events) emission failures
- Claude-specific goal set/clear work through the ACP extension boundary
- Claude process lifecycle

For model/tool/cost analysis, prefer Claude's `claude_code.*` telemetry. For
host integration and protocol behavior, use the adapter telemetry.

## Debug logs

Use `-debug` in standalone mode to write structured adapter debug logs to
stderr:

```bash
acp-go-claude -debug
```

This does not change Claude Code telemetry and does not export OTLP logs by
itself. It is useful when you need local adapter diagnostics next to an OTel
pipeline. Logs stay off stdout so ACP JSON-RPC transport is not corrupted.

## Enable telemetry export

### Standalone

Set standard OpenTelemetry export variables, plus Claude's telemetry switches,
before starting the ACP agent:

```bash
CLAUDE_CODE_ENABLE_TELEMETRY=1 \
CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1 \
OTEL_SERVICE_NAME=acp-go-claude \
OTEL_TRACES_EXPORTER=otlp \
OTEL_METRICS_EXPORTER=otlp \
OTEL_LOGS_EXPORTER=otlp \
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf \
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 \
go run ./cmd/acp-go-claude
```

### Embedded

In [embedded Go](/docs/get-started/run-modes#embedded-go), pass
caller-owned adapter providers and pass Claude telemetry settings through env:

```go
err := claudeacp.Serve(ctx, input, output,
    claudeacp.WithTracerProvider(tracerProvider),
    claudeacp.WithMeterProvider(meterProvider),
    claudeacp.WithTextMapPropagator(propagator),
    claudeacp.WithEnv(map[string]string{
        "CLAUDE_CODE_ENABLE_TELEMETRY":        "1",
        "CLAUDE_CODE_ENHANCED_TELEMETRY_BETA": "1",
        "OTEL_TRACES_EXPORTER":                "otlp",
        "OTEL_METRICS_EXPORTER":               "otlp",
        "OTEL_LOGS_EXPORTER":                  "otlp",
        "OTEL_EXPORTER_OTLP_ENDPOINT":         "http://localhost:4318",
    }),
)
```

Use [`_meta.claude.options.env`](/docs/reference/meta#session-options)
when different sessions need different Claude telemetry settings.

<Warning>
  Do not use `console` exporters in ACP stdio mode. Console exporters write to
  stdout, which is also the ACP JSON-RPC transport.
</Warning>

## Flush short-lived runs

Claude and the adapter batch telemetry. For short smoke tests or local
debugging, lower export intervals so spans, metrics, and logs reach the
collector before the process exits:

```bash
OTEL_METRIC_EXPORT_INTERVAL=1000 \
OTEL_LOGS_EXPORT_INTERVAL=1000 \
OTEL_TRACES_EXPORT_INTERVAL=1000 \
go run ./cmd/acp-go-claude
```

Embedded equivalent:

```go
claudeacp.Serve(ctx, input, output,
    claudeacp.WithEnv(map[string]string{
        "OTEL_METRIC_EXPORT_INTERVAL": "1000",
        "OTEL_LOGS_EXPORT_INTERVAL":   "1000",
        "OTEL_TRACES_EXPORT_INTERVAL": "1000",
    }),
)
```

Use normal production intervals once the pipeline is verified.

## Read traces

Claude trace spans include:

| Span | Purpose |
| --- | --- |
| `claude_code.interaction` | One Claude turn. |
| `claude_code.llm_request` | One Anthropic API request. |
| `claude_code.tool` | One tool call. |
| `claude_code.tool.blocked_on_user` | Time waiting for approval. |
| `claude_code.tool.execution` | Tool execution time. |
| `claude_code.hook` | Hook execution when detailed tracing is enabled. |

Adapter spans use the instrumentation scope:

```text
github.com/savid/acp-go-claude
```

Common adapter spans include:

| Span | Purpose |
| --- | --- |
| `acp.initialize` | ACP initialize handling. |
| `acp.session.prompt` | ACP prompt handling and update streaming. |
| `acp.permission.request` | Permission callback work. |
| `acp.elicitation.request` | User-input callback work. |
| `acp.mcp.bridge.*` | ACP-transport MCP bridge operations. |
| `acp.session_store.*` | External session-store work. |
| `claude.process.*` | Claude discovery, launch, and process lifecycle. |

Claude process lifecycle spans are:

- `claude.process.discover`
- `claude.process.start`
- `claude.process.initialize`
- `claude.process.interrupt`
- `claude.process.close`

## Link traces to your application

Inbound ACP
[`_meta.traceparent`, `_meta.tracestate`, and `_meta.baggage`](/docs/reference/meta#trace-context)
parent adapter spans. Launch-time trace context is injected into Claude process
environment as `TRACEPARENT`, `TRACESTATE`, and `BAGGAGE`.

Claude CLI is a long-lived process per session. Per-prompt trace context inside
Claude is only possible when Claude exposes a stable per-prompt mechanism. New
sessions, loaded sessions, and resumed sessions can still inherit the trace
context that is active at Claude process launch.

## Tag telemetry

Standalone CLI:

Use resource attributes for deployment and ownership tags:

```bash
OTEL_SERVICE_NAME=acp-go-claude \
OTEL_RESOURCE_ATTRIBUTES=deployment.environment=production,service.namespace=agent
```

Embedded Go:

```go
claudeacp.Serve(ctx, input, output,
    claudeacp.WithEnv(map[string]string{
        "OTEL_RESOURCE_ATTRIBUTES": "deployment.environment=production,service.namespace=agent",
    }),
)
```

When the standalone CLI has build info, `service.version` is attached to the adapter
resource. Claude Code exports its own service metadata from the CLI process.

For end-user attribution, pass low-cardinality identifiers as resource
attributes in the session environment. Percent-encode values that may contain
commas, spaces, or equals signs:

```json
{
  "_meta": {
    "claude": {
      "options": {
        "env": {
          "OTEL_RESOURCE_ATTRIBUTES": "enduser.id=user-123,tenant.id=tenant-456"
        }
      }
    }
  }
}
```

Adapter metric families include:

- `acp_go_claude.acp.request.*`
- `acp_go_claude.session.prompt.*`
- `acp_go_claude.session.cancel.count`
- `acp_go_claude.session.active`
- `acp_go_claude.permission.request.*`
- `acp_go_claude.elicitation.request.*`
- `acp_go_claude.mcp.bridge.*`
- `acp_go_claude.session_store.*`
- `acp_go_claude.raw_message.emit.error.count`
- `acp_go_claude.claude.process.exit.count`
- standard `gen_ai.client.*`
- standard `mcp.client.*`

For GenAI semantic attributes emitted by the adapter, set:

```bash
OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental
```

Claude Code also emits its own metric and event names from the CLI. Treat those
as the source of truth for Claude-native model, usage, cost, and tool behavior.

## Embedded ownership

In [embedded Go](/docs/reference/go-api#observability), pass caller-owned
OpenTelemetry providers:

- `WithTracerProvider`
- `WithMeterProvider`
- `WithTextMapPropagator`

The package does not call global OTel setup functions and does not shut down
providers supplied by callers. Embedded callers own exporter configuration,
`ForceFlush`, and `Shutdown`.

The standalone CLI can configure providers from environment
variables and shuts down only the providers it creates.

## Privacy defaults

Adapter spans and metrics do not record these values by default:

- prompt text
- tool input/output
- auth tokens
- MCP bridge tokens
- raw Claude JSON
- Claude goal objective, completion condition, and reason text

Claude Code also redacts sensitive content by default. Only enable Claude's
content-bearing telemetry variables when your observability backend is approved
to store that data:

| Variable | Effect |
| --- | --- |
| `OTEL_LOG_USER_PROMPTS=1` | Include prompt content in Claude telemetry. |
| `OTEL_LOG_TOOL_DETAILS=1` | Include tool input arguments on tool-result events. |
| `OTEL_LOG_TOOL_CONTENT=1` | Include tool input/output bodies on trace events (truncated at 60 KB). |
| `OTEL_LOG_RAW_API_BODIES` | Include raw Anthropic API request/response bodies. Set to `1` for inline bodies (truncated at 60 KB) or `file:<dir>` for untruncated bodies written to disk. |

Use [raw event notifications](/docs/features/raw-events) or explicit
application logs if you need provider JSON for debugging. Do not make those
streams part of the default telemetry path.
