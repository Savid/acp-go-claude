## Credential boundary

Claude account material stays in the Claude config directory the host selects
with `-home` (`WithHome`). The adapter never reads out, logs, or mutates that
material, and ACP `logout` clears only adapter-owned session state. By default
the adapter does not log secrets, prompt text, tool payloads, or raw Claude
event bodies.

## Permission enforcement

Permission prompts are load-bearing and are never bypassed. Decisions stay scoped
to the session that made them and are copied to a forked session only through
intentional fork behavior. `bypass_permissions` and the skip-permissions
capability flag are available only when explicitly enabled — see
[Permissions](/docs/features/permissions).

## Process isolation

On Linux, each session's Claude process runs below a private embedded
supervisor. The supervisor enables `PR_SET_CHILD_SUBREAPER` before launch, so a
tool descendant that double-forks, calls `setsid`, changes process group, or
ignores `SIGINT`/`SIGTERM` is still adopted, identity-checked through `/proc`,
killed, and reaped. The supervisor accepts only the kernel's `ECHILD` result as
the final no-descendants condition; an empty `/proc` scan is not proof because
it can race a fork or reparent. Separate inherited descriptors carry immutable
launch configuration, shutdown control, startup readiness, and the final
quiescence proof. Those descriptors are close-on-exec before Claude starts.
Adapter death therefore closes the sole control writer and makes the supervisor
contain the tree rather than leaving it detached.

On Windows, Claude is created suspended, assigned to a private kill-on-close
Job Object, and only then resumed. Job accounting must report zero active
processes before shutdown succeeds. FreeBSD, OpenBSD, and other unsupported
kernels reject native session launch.

Darwin also rejects native launch by default. An operator can explicitly accept
its weaker boundary with `-darwin-best-effort-containment` or
`WithDarwinBestEffortContainment`. Each launch then gets a fresh mode-`0700`
generation under the selected scratch parent, a random runtime identity, and a
new process group. Shutdown reaps the direct child, sends bounded group
`SIGTERM` then `SIGKILL`, and polls the captured original group until absent.
The fixed cleanup budget is five seconds, with escalation after 500 ms.

That success means only that the direct child was reaped and its original group
was absent. A descendant can call `setsid` and survive outside the group;
Darwin's numeric PGID reuse can make a later negative-PGID signal affect an
unrelated group. Marker correlation is not ownership, inherited markers can be
scrubbed, and managed native-root permits do not bound provider work that
escaped. Best-effort mode therefore emits no provider-descendant snapshots,
including zero, and never claims whole-tree quiescence.

For crash investigation, `acp-go-claude containment diagnose -scratch-dir
<parent>` reads the retained identity registry. Cleanup requires an exact
operator-selected runtime and force acknowledgement:

```sh
acp-go-claude containment cleanup -scratch-dir <parent> -runtime-id <id> -force
```

Cleanup revalidates same-user process identity and both inherited markers,
signals individual correlated processes rather than a recorded PGID, and
retains ambiguous evidence. Neither command proves that marker-scrubbing
escapees are absent. Darwin has no identity-bound process handle here: a PID
can be reused between revalidation and `kill(pid, signal)`, so even individual
signalling can affect unrelated same-user work. The command's fixed five-second
deadline starts before registry and process enumeration.

Turn cancellation is also contained. A native interrupt response is advisory;
the adapter then completes the selected per-session boundary before settling a
cancel, timeout, or caller-context cancellation. Authoritative Linux and
Windows containment covers every descendant. Darwin best effort requires only
direct-child reaping and absence of the original process group, so a `setsid`
escape may remain. Readiness and supervisor exit are not authoritative proof:
Linux requires the dedicated proof descriptor, and an unexpected supervisor
death fails closed.
The next prompt starts a fresh Claude process with
`--resume <session-id>`. Incomplete containment disables that relaunch and
retains the runtime admission instead of making an unsafe capacity claim.

## Input validation

MCP server declarations are validated before Claude launches; unsupported
transports are rejected up front and never reach the CLI (see
[MCP](/docs/features/mcp)). Seed and settings-overlay writes fail closed rather
than overwrite an operator-authored file — see
[Models and config](/docs/features/models-config).

Embedded image data is decoded and structurally validated before a native turn.
Local image output is readable only from the session workspace or the private
session image scratch directory. Reads resolve symlinks, require a regular
file, and enforce the configured byte bound before emission. Remote image URLs
are never fetched. Raw events and raw tool output remove image base64 and
signed query strings, retaining only bounded metadata needed for diagnostics.
