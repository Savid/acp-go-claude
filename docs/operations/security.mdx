## Credential boundary

Claude account material stays in the Claude config directory the host selects
with `-home` (`WithHome`). The adapter never reads out, logs, or mutates that
material, and ACP `logout` clears only adapter-owned session state. By default
the adapter does not log secrets, prompt text, tool payloads, or raw Claude
event bodies.

## Permission enforcement

Permission prompts are load-bearing and are never bypassed. Decisions stay scoped
to the session that made them and are copied to a forked session only through
intentional fork behavior. `bypass_permissions` and the skip-permissions
capability flag are available only when explicitly enabled — see
[Permissions](/docs/features/permissions).

## Process isolation

On Linux, each session's Claude process runs below a private embedded
supervisor. The supervisor enables `PR_SET_CHILD_SUBREAPER` before launch, so a
tool descendant that double-forks, calls `setsid`, changes process group, or
ignores `SIGINT`/`SIGTERM` is still adopted, identity-checked through `/proc`,
killed, and reaped. The supervisor accepts only the kernel's `ECHILD` result as
the final no-descendants condition; an empty `/proc` scan is not proof because
it can race a fork or reparent. Separate inherited descriptors carry immutable
launch configuration, shutdown control, startup readiness, and the final
quiescence proof. Those descriptors are close-on-exec before Claude starts.
Adapter death therefore closes the sole control writer and makes the supervisor
contain the tree rather than leaving it detached.

On Windows, Claude is created suspended, assigned to a private kill-on-close
Job Object, and only then resumed. Job accounting must report zero active
processes before shutdown succeeds. Darwin, FreeBSD, OpenBSD, and other kernels
without an equivalent unescapable boundary reject native session launch. A
process group alone is never accepted as proof because a descendant can leave
it.

Turn cancellation is also process-tree contained. A native interrupt response
is advisory; the adapter then closes the per-session tree and does not settle
the cancel, timeout, or caller-context cancellation until every descendant is
proved gone. Readiness and supervisor exit are not proof: Linux requires the
dedicated proof descriptor, and an unexpected supervisor death fails closed.
The next prompt starts a fresh Claude process with
`--resume <session-id>`. Failed quiescence proof disables that relaunch and
retains the runtime admission instead of making an unsafe capacity claim.

## Input validation

MCP server declarations are validated before Claude launches; unsupported
transports are rejected up front and never reach the CLI (see
[MCP](/docs/features/mcp)). Seed and settings-overlay writes fail closed rather
than overwrite an operator-authored file — see
[Models and config](/docs/features/models-config).
