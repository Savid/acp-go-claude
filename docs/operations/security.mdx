title: "Security"
description: "The trust boundaries an operator relies on when running the adapter"
---

## Credential boundary

Claude account material stays in the Claude config directory the host selects
with `-home` (`WithHome`). The adapter never reads out, logs, or mutates that
material, and ACP `logout` clears only adapter-owned session state. By default
the adapter does not log secrets, prompt text, tool payloads, or raw Claude
event bodies.

## Permission enforcement

Permission prompts are load-bearing and are never bypassed. Decisions stay scoped
to the session that made them and are copied to a forked session only through
intentional fork behavior. `bypass_permissions` and the skip-permissions
capability flag are available only when explicitly enabled — see
[Permissions](/docs/features/permissions).

## Process isolation

Each session's Claude process is started in its own process group and, on Unix
platforms, is configured to receive a parent-death signal, so a crashed or
killed adapter does not leave orphaned Claude processes behind.

## Input validation

MCP server declarations are validated before Claude launches; unsupported
transports are rejected up front and never reach the CLI (see
[MCP](/docs/features/mcp)). Seed and settings-overlay writes fail closed rather
than overwrite an operator-authored file — see
[Models and config](/docs/features/models-config).
