title: "Troubleshooting"
description: "Diagnose missing tools, questions, persistence failures, and unavailable authentication"
---

## MCP tools missing during session establishment

Claude fixes its MCP tool registry at process startup. The adapter starts a
replacement process immediately before the first MCP-bearing prompt so a
session-bound endpoint can expose its authorized tools. The original process
settles before replacement, and both use the same private MCP configuration.
Check that the endpoint exposes the intended tools when that first prompt
starts. See [MCP](/docs/features/mcp).

## A completed response becomes a prompt error

A native result alone does not complete a prompt. The adapter also waits for
its transcript prefix to reach the session store before terminal lifecycle
`idle` and the prompt response. A store failure fails that boundary even when
text has already streamed. Check the store's availability and write errors;
see [Session store](/docs/features/session-store).

## AskUserQuestion never reaches the host

Claude's `AskUserQuestion` requires an explicit non-null `form` elicitation
capability during initialize. An absent capability, `{}`, both modes set to
`null`, or URL-only support cannot carry that form. Secret-marked questions
are also refused. See [Elicitation](/docs/features/elicitation).

## An answer arrives after cancellation

Cancellation resolves pending permission and elicitation requests. A late
answer is not applied to the cancelled turn. Retry through a new prompt if the
work should continue; see [Prompt streaming](/docs/core/prompt-streaming).

## Provider authentication is unavailable

The `_claude/auth/*` methods require a usable `WithProviderAuthRoot`, non-bare
mode, and no configured static authentication. The credential check uses the
same native environment as process launch. For managed execution, inspect the
host authority's environment and the explicit overlays. Direct-home consent
controls native-login disconnect execution, not the advertised leg count.
See [Authentication](/docs/features/authentication).

## Integration tests skip

The integration tier requires `ACP_GO_CLAUDE_RUN_INTEGRATION=1`. Compiled-binary
tests also require `ACP_GO_CLAUDE_AGENT_BINARY` to name a built agent binary.
`make test-integration-cover` supplies that binary and `GOCOVERDIR`. Model-token,
attended, keystore, and browser tests have separate opt-in targets; use only the
tier whose prerequisites and costs you intend to enable.
