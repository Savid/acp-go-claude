## Methods

Core methods handled through the ACP SDK connection: initialize, session
create/load/resume/list/delete, prompt, cancel, close, authenticate, logout, and
the session configuration methods. Unsupported methods return a uniform JSON-RPC
method-not-found error.

`session/new`, `session/load`, `session/resume`, and `_claude/session/fork` all
require an absolute `cwd`. A relative one is rejected with `-32602`
`{"error":"unsupported","field":"cwd"}` before any native process or store entry
exists.

Every `_claude/*` request whose params cannot be decoded, or which fail
validation as a whole, is rejected with `-32602`
`{"error":"unsupported","field":"params"}`; when one member is at fault, `field`
names that member instead — for example
`{"error":"unsupported","field":"mcpServers[0]"}` on a fork whose MCP server
entry declares no transport this adapter can carry. The decoder's own Go error
text never reaches the wire.

### `_claude/auth/*`

Session-scoped methods that broker Claude's native login, setup tokens, and
Anthropic API keys. They exist
only while `WithProviderAuthRoot` names a usable durable directory, bare mode
is disabled, and no agent-wide static authentication overrides that directory's login;
otherwise every one returns method-not-found, and the initialize capability
lists none. Native-login disconnect requires `WithProviderAuthDirectHome`
equal to `WithHome`; secret-backed disconnect only ends the recorded lineage.
See [Authentication](/docs/features/authentication).

| Method | Params | Result |
| --- | --- | --- |
| `_claude/auth/methods` | `{sessionId}` | `{providers, generation}` |
| `_claude/auth/authorize` | `{sessionId, providerId, connectionId, methodsGeneration, method, authorizeRequestId, inputs?}` | `{interaction, url, message, callbackInput, flowId, flowExpiresAt}` |
| `_claude/auth/callback` | `{sessionId, providerId, method, flowId, input}` | `{flowId}` |
| `_claude/auth/status` | `{sessionId, providerId, flowId}` | `{flowId, state, reason?}` |
| `_claude/auth/cancel` | `{sessionId, providerId, flowId}` | `{flowId}` |
| `_claude/auth/inventory` | `{sessionId}` | `{entries}` |
| `_claude/auth/credential` | `{sessionId, providerId, flowId}` | `{connectionId, revision, bindingGeneration, credential}` |
| `_claude/auth/disconnect` | `{sessionId, providerId, connectionId, bindingGeneration}` | `{}` |

Every request and result object is closed: an unknown, duplicate, or misplaced
field is rejected with `-32602` naming its path, and every time value is Unix
epoch milliseconds. `state` is one of `pending`, `authenticated`, `saved`, `failed`,
`cancelled`, or `expired`; `reason` appears only on the three terminal-negative
states. `connectionId` is caller-minted and bounded to at most 128 bytes of
`A-Z`, `a-z`, `0-9`, `-`, and `_`; every leg that carries one checks it before
the value is compared or recorded, and anything outside that shape is `-32602`
naming `connectionId`. A failure after parameters validate is `-32000` with:

```json
{
  "error": "claude_auth_failed",
  "cause": "native_veto",
  "providerId": "anthropic",
  "method": "login",
  "flowId": "…",
  "retryable": false
}
```

`cause` is one of `native_veto`, `provider_refused`, `transport`, `process`,
`timeout`, `harvest_failed`, `unsupported_variant`, `flow_expired`,
`flow_state`, `flow_cancelled`, `policy`, or `binding_conflict`. The shape
carries no native message, response body, or free-form field: a refusal is
reported by its `cause` alone.

`binding_conflict` comes only from `_claude/auth/disconnect`, and it means the
`connectionId` and `bindingGeneration` you sent do not match the binding the
adapter recorded — no entry, a different connection, or a generation already
spent. Nothing is mutated: no generation bump and no native logout. Reconnect to
get a current binding; retrying the same one never succeeds. It is deliberately
not `policy`, which is the adapter refusing on its own terms and which
reconnecting does not clear. `_claude/auth/disconnect` answers `policy` when the
configured config directory no longer names the directory the consent gate
resolved at startup: the removal is not undoable, so a repointed path is refused
rather than cleared.

### `_claude/rateLimits`

Reads structured provider quota observations. `RateLimitsRequest` accepts optional
`providerId` and `sessionId` strings. Absent params, `null`, and `{}` are
accepted. A supplied session must identify an exact live session; it selects
that session's effective authentication and endpoint. The omitted provider is
`anthropic`, Claude's single provider identity. Other explicit provider IDs
return `unsupported` with their spelling preserved.

```json
{
  "providerId": "anthropic",
  "availability": "available",
  "pools": [{
    "id": "subscription",
    "planType": "max",
    "windows": [{
      "id": "five_hour",
      "usedPercent": 92,
      "observedAt": "2026-09-08T03:00:00Z",
      "resetsAt": "2026-09-08T06:00:00Z"
    }]
  }]
}
```

`availability` is `available`, `unavailable`, or `unsupported`. Available results
contain at least one pool and no `reason`. Unavailable results have empty
`pools` and a reason: `not_observed`, `not_authenticated`, `read_failed`,
`disabled`, or `session_required`. Unsupported results have empty `pools` and
no reason. Unknown request fields, duplicate fields, malformed JSON, and empty
selectors produce invalid params with `{"error":"unsupported","field":"…"}`.

Each pool has an opaque `id`, optional `label` and `planType`, required `windows`,
and optional monetary `balances`. Window fields are `id`, optional
`usedPercent`, `durationSeconds`, and `status`, required `observedAt`, and
optional `resetsAt`. A window reports a percentage or status (`ok`, `warning`,
or `exhausted`); a supplied duration is a positive `int64` number of seconds.
A balance has `id`, optional `used`, `limit`, `remaining`, `uncapped`, and `resetInterval`,
required `observedAt`, and optional `resetsAt`; monetary values contain `amount`
and a three-letter uppercase `currency`. Values use major currency units;
`used` and `limit` are nonnegative, while `remaining` may be negative. Values
within one balance share a currency. A balance reports at least one monetary
value or `uncapped:true`; uncapped balances omit `limit` and `remaining`.
`resetInterval` is `daily`, `weekly`, or `monthly`. Percentages above 100 are
preserved. Numeric observations are finite. IDs are unique within their
collection, and each pool contains a window or balance. Timestamps use UTC `Z`.

#### Claude sources and availability

A live session uses Claude's experimental structured `get_usage` control
request with `skip_behaviors:true`. It sends no user prompt and reads no
slash-command prose. Normalization follows the structured usage schema in
[Agent SDK 0.3.263](https://www.npmjs.com/package/@anthropic-ai/claude-agent-sdk/v/0.3.263).
Claude Code 2.1.263 accepted the control request; native responses can contain
no quota observations. Older or incompatible native control implementations
can return `unavailable/read_failed`.

`five_hour` and `seven_day` windows belong to the `subscription` pool. Native
`seven_day_oauth_apps`, `seven_day_opus`, and `seven_day_sonnet` allowances
remain separate pools, each with a `seven_day` window. Other native
`model_scoped` entries use `model:<display_name>` pool IDs and a `usage` window.
The source supplies percentages directly. The known `Fable` entry has a
`durationSeconds` of `604800`, matching its weekly allowance. Other model-scoped
durations, status, and monetary balances are omitted: this reader has no verified
mapping for those facts, including the units and currency of native `extra_usage`
credit values.
`subscription_type`, when present, becomes `planType`.

Every quota read first uses the addressed session's native control connection.
A call without a session returns `unavailable/session_required`. When native
usage has no usable windows, the default `WithClaudeDirectAPI(true)` permits
setup-token header probes: at most one Fable `POST /v1/messages`, then one Haiku
request only if Fable supplies no usable quota. Both use billable `max_tokens:1`.
The probes use the exact session process's captured `CLAUDE_CODE_OAUTH_TOKEN` and
`ANTHROPIC_BASE_URL` (default `https://api.anthropic.com`). Fable uses
`ANTHROPIC_DEFAULT_FABLE_MODEL`, then `claude-fable-5-1`. The Haiku fallback uses
`ANTHROPIC_SMALL_FAST_MODEL`, then `ANTHROPIC_DEFAULT_HAIKU_MODEL`, then
`claude-haiku-4-5`. It makes no credential-store lookup, refresh, or login change.

The Fable request runs through a temporary Claude process with its own empty
home and working directory, tools disabled, and no session persistence. Its
temporary tree lives under `WithScratchDir` (default `os.TempDir()`), so the
session's working directory need not be writable. A private loopback bridge
forwards only the first request matching the captured setup
token, Fable model, and one-token limit. Further native attempts cannot reach the
upstream endpoint. The native process supplies its own request format; the bridge
discards generated content. Managed launches and temporary trees use the session's
host authority. Process settlement and successful tree reclaim precede removal;
failed cleanup retains its owner for client close and prevents fallback.

The fallback requires a readable native `get_settings.effective` snapshot.
It refuses differing authentication or routing overrides, `apiKeyHelper`, custom
request headers, bare mode, and environment credentials or cloud selectors that
take precedence over a setup token. It rechecks the settings after the probe and discards an
observation if the effective context changed. This follows Claude's documented
[authentication precedence](https://code.claude.com/docs/en/authentication#authentication-precedence).
`WithClaudeDirectAPI(false)` preserves usable native observations. If an eligible
setup-token probe is the only acquisition path, disabling it returns
`unavailable/disabled`. With no eligible fallback, native
`rate_limits_available:false` remains `unsupported`, an empty supported snapshot
is `unavailable/not_observed`, and a failed control read is
`unavailable/read_failed`. HTTP 401 probe failures return
`unavailable/not_authenticated` and stop further probes. Other final probe
failures return `unavailable/read_failed`.
Queued native probes honor caller cancellation while another probe is active.

Successful responses and HTTP 429 responses can supply
`anthropic-ratelimit-unified-5h-*`, `anthropic-ratelimit-unified-7d-*`, and
`anthropic-ratelimit-unified-7d_oi-*` headers.
Their utilization fractions become percentage points in the same `subscription`
pool and `five_hour`/`seven_day` windows as the native reader. The `7d_oi` allowance
uses `model:Fable` / `usage` with `durationSeconds:604800`, matching native Fable
model-scoped usage and its [weekly allowance](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan).
Invalid optional resets are omitted. The probe refuses redirects, discards the response body
within a 1 MiB bound, and reports failures without remote error text. It opens
a direct connection to the configured endpoint; native proxy, custom TLS, and
custom header settings are not reproduced.

Acquisition has a total 30-second deadline, shortened by the caller's deadline.
Caller cancellation remains a request error. No adapter cache is maintained;
`observedAt` records receipt of the native response or quota headers. Observations
past their reset or 60-second freshness limit are omitted. A changed auth
binding, session process, or configured environment discards an in-flight result.
Closed, poisoned, and unknown sessions and agent/authority failures retain their
usual request errors. The method emits no quota notifications and advertises no
quota capability metadata.

## Turn-failure contract

A native turn failure terminates `session/prompt` with a JSON-RPC error and no
`PromptResponse`; it is never reported as an ACP stop reason. Every failure uses
one uniform shape so a host can classify it without vendor parsing. The error is
JSON-RPC code **`-32603`** with a `data` object:

| Field | Value |
| --- | --- |
| `error` | `claude_turn_failed` |
| `cause` | one of the causes below |
| `message` | the real native cause text, never a fixed placeholder |

The `cause` vocabulary:

| Cause | Meaning |
| --- | --- |
| `process_exit` | The Claude process died; `message` carries only the closed exit status, never captured stderr. |
| `transport` | Stream close, malformed frame, or client-lifecycle break; `message` carries the cause the adapter observed. |
| `provider` | Claude reported an error in its result frame (including auth failures); `message` carries the provider cause the frame named. |
| `timeout` | A `WithTurnTimeout` deadline expired; the selected native containment boundary completed before settlement. |

`message` on this envelope is the real cause, recovered before the failure is
surfaced, because a host cannot act on "something broke". For a `provider`
failure the adapter reads the result frame's singular `error` field, falling
back to its `result` text — the field Claude actually populates for an auth
refusal — and uses a constant only when the frame names no cause at all.

Nothing else from the frame crosses: the subtype, the error list, the
structured output, and the raw body are never copied onto the wire, process
stderr is never retained, and no `providerCredential` member is emitted — the
only credential signal Claude gives here is text, and that member may be
derived only from a structured native signal.

`session/close` has one refusal of its own. It settles behind the session's
settlement barrier, so a caller whose wait for the in-flight turn ends before that
turn releases the session is told the close settled nothing. Which answer that is
depends on why the wait ended:

| Wait ended by | Answer |
| --- | --- |
| The caller cancelling its own request | `-32800` `Request cancelled` |
| Any other expiry, such as a deadline | `-32600` `Invalid request` with `{"error":"claude_session_close_unsettled","message":<barrier wait error>}` |

Neither is `-32603`: nothing failed internally, the containment boundary was
simply never reached. Nothing was contained, no quiescence was stated, and the id
still names its live session — the next close settles it. The `message` carries
the barrier-wait error, not anything the native process reported. A same-id load,
resume, or fork over an instance whose close settled nothing is refused the same
way.

A close that reached the boundary and failed a rung of it keeps the id too, and
returns the failure it earned. The id stops resolving only behind a close that
completed every rung it owed, so the next `session/close` retakes the boundary
rather than repeating an answer.

`session/delete` runs the other way round. It writes its durable tombstone first
and hides the id with it, and only then cancels, closes, and cleans up. A
teardown that does not finish is reported as the delete's error, but the
tombstone is already durable and the session is already hidden from
`session/list`, `session/load`, `session/resume`, and every other session-scoped
method; the instance stays held so the next `session/delete` finishes what the
first started. No write behind a tombstone recreates the row, and nothing is
installed behind one either: a `session/load` or `session/resume` whose native
process finished starting after the tombstone landed is refused with the
unknown-session error and torn down, rather than registered under an id no host
could address again.

Delete's teardown meets the same settlement barrier, so it has the same refusal
under a name of its own:

| Wait ended by | Answer |
| --- | --- |
| The caller cancelling its own request | `-32800` `Request cancelled` |
| Any other expiry, such as a deadline | `-32600` `Invalid request` with `{"error":"claude_session_delete_unsettled","message":<barrier wait error>}` |

It is named apart from `claude_session_close_unsettled` because it reports a
different state. A refused close settled nothing and its id still names a live
session; a refused delete already deleted the session — the tombstone is durable
and the id is hidden — and owes only the teardown, which the next
`session/delete` takes. Any other teardown failure, such as a containment or
cleanup error, is a real internal failure and is still answered `-32603`.

An image output the adapter will not ship — `invalid_base64`, `not_a_raster`,
`media_type_mismatch`, `missing_file`, `path_not_allowed`, or `too_large` — is
recoverable. It fails that tool call only, carrying fixed guidance as the call's
own content, and the turn keeps running; an assistant image, which has no tool
call to attribute to, is replaced by the same guidance as agent text. Only
`storage_failed` still ends the prompt, using the same `-32603` envelope with
`cause: "transport"` plus `stage: "image_output"`, and emitting a status-only
failed update for the tool call first.

<Note>
This adapter advertises no ACP auth methods, so an authentication failure is a
`provider` failure under `-32603` — it never emits the `-32000` auth-required
variant. A user cancel that races a timeout resolves as a successful `cancelled`
response, not a failure. `session/cancel`, timeout expiry, and caller-context
cancellation do not settle on a native interrupt acknowledgement alone. With a
host authority, `NativeProcess.Wait` must reach terminal settlement after the
protocol shutdown or `Revoke`. An incomplete selected boundary is a
`transport` failure, retains prepared trees, and cannot be lazily relaunched.
</Note>

## Internal-error contract

Every `-32603` this adapter emits away from a prompt turn — on `initialize`, a
session lifecycle request, `session/close`, `session/delete`, a slash-command
route, or an extension method — carries exactly one closed, vendor-prefixed token
in `data.error`, and the JSON-RPC `message` stays the constant `Internal error`.
The data carries no `message` member, no Go error text, and no native harness
text: a more specific fact rides a documented closed `class` or `cause` token, or
the adapter's log, and never the wire.

| `data.error` | Condition | Additional members |
| --- | --- | --- |
| `claude_invalid_options` | The agent was constructed with an option set it will not serve under. `NewAgent` returns no error, so the verdict is delivered on the wire at `initialize` and at every session-establishing entry point. | Optional `field` naming the refused option when exactly one option is refused, such as `concurrencyLimits.maxActiveSessions`. |
| `claude_restore_failed` | `session/load` or `session/resume` found a store entry for the session and could not restore it — the store could not be read, the stored session configuration could not be decoded, or the stored transcript could not be replayed. The entry is neither deleted nor tombstoned by the failure. | none |
| `claude_session_poisoned` | A native invariant violation poisoned the session, which then refuses every operation but `session/close` and `session/delete`. | `cause`, exactly one of `conversation_reset` or `session_id_drift`. |
| `claude_internal_failure` | Every failure the tokens above cannot classify. | `class`, one of `cancelled`, `deadline`, `internal`, `containment_incomplete`, `lifecycle_violation`, `autonomous_stream_failed`, `store_commit_failed`, `session_delete_untombstoned`. |

The `class` values, and what a host does with each:

| `class` | Meaning |
| --- | --- |
| `cancelled` | The work was abandoned by a cancellation this answer could not report as `-32800`. |
| `deadline` | A handler or client-call deadline expired. |
| `internal` | An unclassified adapter failure. Retry is reasonable. |
| `containment_incomplete` | A native process tree could not be contained, so the agent is latched until the host recovers the identity. Retrying the same request will not clear it. |
| `lifecycle_violation` | A lifecycle-stream invariant broke — an action lost its owner, an announcement was not written, or an event could not be delivered. |
| `autonomous_stream_failed` | The addressed incarnation was contained because its between-prompt output could not be projected. A relaunch clears it. |
| `store_commit_failed` | A turn streamed content the session store then failed to hold. The harness produced the turn correctly; the adapter's durability boundary is what broke. |
| `session_delete_untombstoned` | A `session/delete` whose durable tombstone never landed. Nothing was deleted and the id still names whatever it named. |

`claude_turn_failed` above is the prompt turn's own token and is the only one
that carries a `message`. This adapter runs one native `claude` process per
logical session rather than multiplexing sessions over a shared runtime, so it
emits no shared-runtime-loss token: a process that exits is relaunched by the
next operation that needs it.

A construction verdict is never `-32602` and a poisoned session is never
`-32600`: neither is a defect in the caller's request.
