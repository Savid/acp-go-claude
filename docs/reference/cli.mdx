`acp-go-claude` speaks ACP over stdin/stdout. Flags use Go's single-dash syntax.

```sh
acp-go-claude -path /usr/local/bin/claude -home /tmp/claude-home -model sonnet -claude-permission-mode default
```

## Optional standalone isolation policy

Serve mode needs no isolation policy: omitting
`-process-isolation-config` launches native work as the identity the command
already runs as, over a deterministic capture of the ambient environment, and
`-home` keeps its ordinary managed-home meaning. Supplying
`-process-isolation-config=/absolute/path/process-isolation.json`
selects the Linux-only hardened standalone mode; a policy that fails to load
or validate refuses startup before serving, with no ordinary-mode fallback.
The policy must be a root-owned, single-link regular file with mode `0600`.
Every component is opened from `/` without following symlinks, and every
ancestor must be root-owned and not writable by group or other. Unknown JSON
fields and trailing JSON values are rejected.

```json
{
  "uid": 20001,
  "gid": 20001,
  "standaloneOwnerId": "claude-deployment-1",
  "standaloneStateRoot": "/var/lib/acp-go-claude",
  "baseEnvironment": {
    "PATH": "/usr/local/bin:/usr/bin:/bin",
    "HOME": "/var/lib/acp-go-claude",
    "USER": "acp-go-claude",
    "LOGNAME": "acp-go-claude",
    "LANG": "C.UTF-8"
  },
  "inheritEnvironment": []
}
```

`standaloneOwnerId` is the nonsecret, case-sensitive deployment identity:
1--256 ASCII bytes, beginning alphanumeric, with remaining bytes limited to
alphanumerics and `._:@/-`. `standaloneStateRoot` is the existing dedicated
durable provider state root, is neither `/` nor equal to or beneath
`/var/lib/acp-go/agent-identities`, and must equal the configured native home. Its clean
absolute UTF-8 path is limited to 4096 bytes with no control character, and
Linux resolves the complete path componentwise from `/` without following
symlinks or magic links. Every ancestor is root-owned and not group/world
writable; the final directory is owned by the configured UID:GID with mode
`0700`. It binds the exact path, device, and inode.

The supervisor must run as root. The UID/GID must name a nonroot account with
that same-name private primary group, no supplementary groups, and a target-owned mode
`0700` home matching `HOME`, reached without symlinks beneath protected
root-owned ancestry; `/root` and `/nonexistent` are forbidden. `USER` and
`LOGNAME` must match the account.
`PATH` must contain existing canonical absolute directories. The child gets
only `baseEnvironment` plus variables explicitly named in
`inheritEnvironment`; identity, search-path, loader, interpreter, XDG/native
home, and adapter-private variables cannot be inherited. Unset or duplicate
inheritance entries fail startup. Darwin, Windows, and other platforms refuse
standalone native mode rather than weakening this contract.

Provision the target as a locked system account with a non-login shell, its
same-name private group, and no sudo policy. Its UID and primary GID cannot be
shared by another account. Password locking is not a substitute for disabling
login paths, and a locked account still needs the validated private writable
home for native tools.

## Flags

| Flag | Purpose |
| --- | --- |
| `-path` | Claude CLI executable (default: search `PATH`). |
| `-process-isolation-config` | Optional absolute path to the standalone Linux isolation policy described above. Omitted launches native work as the current identity. |
| `-home` | Claude config directory (`CLAUDE_CONFIG_DIR`) for launched sessions. In hardened mode it defaults to and, when set, must equal `standaloneStateRoot`; ordinary mode accepts an independent clean path. |
| `-scratch-dir` | Parent directory for ephemeral session scratch; empty means the system temp directory. |
| `-provider-auth-root` | Durable host-owned directory holding the values-free provider-auth ledger. Empty, bare mode, or agent-wide static authentication leaves every `_claude/auth/*` method unadvertised. |
| `-provider-auth-direct-home` | Exact Claude config directory the operator consents to native-login disconnect clearing. Secret-backed disconnect never clears it. |
| `-model` | Default Claude model. |
| `-seed-file` | Write a host file into the config dir as `<relpath>=<hostpath>`; repeatable. Requires `-home`. |
| `-claude-settings-file` | Settings-overlay relpath under the config dir passed as `--settings`. Requires `-home`. |
| `-claude-bare` | Launch Claude with `--bare`. |
| `-claude-hide-auth` | Hide Claude subscription terminal auth methods. |
| `-claude-permission-mode` | Default Claude permission mode. |
| `-claude-system-prompt` | Default system prompt. |
| `-debug` | Emit debug logs to stderr. |
| `-version` | Print adapter version and exit. |

<Note>
Not every embedded option has a flag. Turn timeouts, concurrency limits,
OpenTelemetry providers, and the session store are embedded-Go only — configure
them with the [Go API](/docs/reference/go-api) options such as `WithTurnTimeout`
and `WithSessionStore`.
</Note>

## Darwin containment operations

These commands inspect and clean retained Darwin best-effort generations left
by an embedded host; the standalone command does not launch native work there:

```sh
acp-go-claude containment diagnose -scratch-dir <parent>
acp-go-claude containment cleanup -scratch-dir <parent> -runtime-id <id> -force
```

`diagnose` is read-only. `cleanup` requires an exact lowercase 128-bit runtime
id and revalidates same-user process identity plus both inherited markers before
signalling individual candidates. Both write one JSON object to stdout. Their
correlation is not ownership or proof of absence: descendants can escape the
original process group with `setsid` and can scrub inherited markers. A PID can
also be reused between revalidation and signal, so cleanup can affect unrelated
same-user work. Its fixed five-second deadline starts before enumeration.
