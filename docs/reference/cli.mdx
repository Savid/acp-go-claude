`acp-go-claude` speaks ACP over stdin/stdout. Flags use Go's single-dash syntax.

```sh
acp-go-claude -path /usr/local/bin/claude -home /tmp/claude-home -model sonnet -claude-permission-mode default
```

## Flags

| Flag | Purpose |
| --- | --- |
| `-path` | Claude CLI executable (default: search `PATH`). |
| `-home` | Claude config directory (`CLAUDE_CONFIG_DIR`) for launched sessions. |
| `-scratch-dir` | Parent directory for ephemeral session scratch; empty means the system temp directory. |
| `-provider-auth-root` | Durable host-owned directory holding the values-free provider-auth ledger. Empty, bare mode, or agent-wide static authentication leaves every `_claude/auth/*` method unadvertised. |
| `-provider-auth-direct-home` | Exact Claude config directory the operator consents to native-login disconnect clearing. Secret-backed disconnect never clears it. |
| `-darwin-best-effort-containment` | On Darwin only, explicitly accept process-group containment and its escaped-descendant and numeric-PGID-reuse risks. Darwin fails closed without it; other platforms reject it. |
| `-model` | Default Claude model. |
| `-seed-file` | Write a host file into the config dir as `<relpath>=<hostpath>`; repeatable. Requires `-home`. |
| `-claude-settings-file` | Settings-overlay relpath under the config dir passed as `--settings`. Requires `-home`. |
| `-claude-bare` | Launch Claude with `--bare`. |
| `-claude-hide-auth` | Hide Claude subscription terminal auth methods. |
| `-claude-permission-mode` | Default Claude permission mode. |
| `-claude-system-prompt` | Default system prompt. |
| `-debug` | Emit debug logs to stderr. |
| `-version` | Print adapter version and exit. |

<Note>
Not every embedded option has a flag. Turn timeouts, concurrency limits,
OpenTelemetry providers, and the session store are embedded-Go only — configure
them with the [Go API](/docs/reference/go-api) options such as `WithTurnTimeout`
and `WithSessionStore`.
</Note>

## Darwin containment operations

These commands inspect and clean retained Darwin best-effort generations:

```sh
acp-go-claude containment diagnose -scratch-dir <parent>
acp-go-claude containment cleanup -scratch-dir <parent> -runtime-id <id> -force
```

`diagnose` is read-only. `cleanup` requires an exact lowercase 128-bit runtime
id and revalidates same-user process identity plus both inherited markers before
signalling individual candidates. Both write one JSON object to stdout. Their
correlation is not ownership or proof of absence: descendants can escape the
original process group with `setsid` and can scrub inherited markers. A PID can
also be reused between revalidation and signal, so cleanup can affect unrelated
same-user work. Its fixed five-second deadline starts before enumeration.
