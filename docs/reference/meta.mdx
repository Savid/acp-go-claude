ACP reserves [`_meta`](https://agentclientprotocol.com/protocol/extensibility)
for extension metadata on requests, responses, and notifications. Portable
clients should ignore metadata they do not understand.

The `claude` metadata namespace belongs to this adapter. It means the local
Claude CLI / Claude Code integration, not a generic Anthropic API surface.

## Trace context

Inbound ACP `_meta` can contain W3C trace context:

```json
{
  "traceparent": "00-...",
  "tracestate": "...",
  "baggage": "..."
}
```

The adapter uses this to parent its own spans. It also injects launch-time
trace context into Claude process environment for new, loaded, and resumed
sessions. See [Observability](/docs/operations/observability#link-traces-to-your-application).

## Session options

```json
{
  "claude": {
    "options": {
      "bare": true,
      "env": {
        "EXAMPLE": "value"
      },
      "systemPrompt": "Be concise.",
      "model": "sonnet",
      "permissionMode": "acceptEdits",
      "additionalDirectories": ["/workspace/shared"],
      "outputFormat": {
        "type": "json_schema",
        "schema": {
          "type": "object",
          "properties": {
            "ok": { "type": "boolean" }
          },
          "required": ["ok"],
          "additionalProperties": false
        }
      }
    }
  }
}
```

All paths in `additionalDirectories` must be absolute. The Go helper for
building this object is
[`ClaudeOptions`](/docs/reference/go-api#claudeoptions).

`outputFormat` configures Claude Code structured output with
`claude --json-schema`. It is a session-start option, so attach it to
`session/new`, `session/load`, `session/resume`, or `session/fork`; it is not
accepted per prompt.

## Raw event emission

```json
{
  "claude": {
    "emitRawSDKMessages": true
  }
}
```

Or use filters:

```json
{
  "claude": {
    "emitRawSDKMessages": [
      { "type": "assistant" },
      { "type": "system", "subtype": "init" }
    ]
  }
}
```

See [Raw Claude events](/docs/features/raw-events) for selection behavior and
payload details.

## Session response metadata

Session responses include Claude-specific model variant metadata and the
current goal snapshot:

```json
{
  "claude": {
    "modelId": "sonnet",
    "variant": "medium",
    "availableVariants": ["low", "medium", "high"],
    "goal": null
  }
}
```

The portable model/config surface is documented in
[Models and config](/docs/features/models-config).

## Goals

Goal state is a Claude-specific incubation surface under `_meta.claude.goal`.
It is session metadata, not a Claude launch option:

```json
{
  "claude": {
    "goal": {
      "objective": "Ship OAuth login",
      "completionCondition": "Browser login works and tests pass",
      "status": "active",
      "createdAt": "2026-05-27T00:00:00Z",
      "updatedAt": "2026-05-27T00:00:00Z",
      "completedAt": null,
      "reason": null,
      "reasonCode": null,
      "goalId": null,
      "source": "client"
    }
  }
}
```

`session_info_update` emits goal changes as `_meta.claude.goal`. The goal value
is a full snapshot; optional fields are explicit `null` values so clients using
ACP's recursive `_meta` merge semantics clear stale nested fields. Clearing a
goal is `_meta.claude.goal: null`.

The `_claude/session/setGoal` extension method sets or clears adapter-visible
goal state. It does not interrupt Claude or rewrite an active turn. Claude-native
`/goal` rows from transcript mirror frames are mapped into the same metadata
shape when available. See [Goals](/docs/features/goals).

## Model metadata

Model entries and model config option values can include Claude-specific
capability hints:

```json
{
  "claude": {
    "supportedEffortLevels": ["low", "medium", "high", "xhigh", "max"],
    "supportsAutoMode": true,
    "contextWindow": 1000000
  }
}
```

These fields are emitted under each model's `_meta.claude` object when Claude
reports or the adapter can infer them. The selected effort control remains the
standard `thought_level` config option.

## Structured output result metadata

When Claude returns structured output, the final result-derived usage update
includes the validated object:

```json
{
  "claude": {
    "structuredOutput": {
      "ok": true
    }
  }
}
```

The intermediate Claude `StructuredOutput` tool call is hidden from normal ACP
tool updates. Enable [raw Claude events](/docs/features/raw-events) if a host
needs to inspect the provider-native tool frame.

## Usage metadata

ACP's standard per-turn token breakdown is `PromptResponse.usage`. This adapter
maps Claude cache counters directly:

```text
cache_read_input_tokens      -> cachedReadTokens
cache_creation_input_tokens  -> cachedWriteTokens
reasoning_output_tokens      -> thoughtTokens
```

`usage_update` remains the ACP context/cost signal (`size`, `used`, and
optional `cost`). Result-derived and streaming usage updates also include the
same Claude token breakdown under `_meta.claude.usage` for clients that consume
the update stream:

```json
{
  "claude": {
    "usage": {
      "inputTokens": 10,
      "outputTokens": 77,
      "cachedReadTokens": 0,
      "cachedWriteTokens": 26609,
      "thoughtTokens": 0,
      "totalTokens": 26696
    }
  }
}
```

When Claude reports per-model usage, final result-derived usage updates also
include `_meta.claude.modelUsage`:

```json
{
  "claude": {
    "modelUsage": {
      "claude-haiku-4-5-20251001": {
        "inputTokens": 450,
        "outputTokens": 89,
        "cachedReadTokens": 0,
        "cachedWriteTokens": 26609,
        "contextWindow": 200000
      }
    }
  }
}
```

## Initialize capability metadata

The initialize response advertises:

- `claude.promptQueueing`
- `claude.sessionImport`
- `claude.sdkMessages`
- `claude.outputFormat`
- `claude.goals`
- `claude.workflows`

These fields are intentionally Claude-specific. Portable clients should rely on
the normal ACP fields first. Method support is listed in
[ACP methods](/docs/reference/acp-methods).

Example:

```json
{
  "claude": {
    "promptQueueing": {
      "scope": "session",
      "sameSession": true
    },
    "sessionImport": {
      "scope": "session",
      "format": "claude-jsonl",
      "methods": {
        "import": "_claude/session/import",
        "importChunk": "_claude/session/importChunk",
        "commitImport": "_claude/session/commitImport",
        "abortImport": "_claude/session/abortImport"
      }
    },
    "sdkMessages": {
      "scope": "session",
      "method": "_claude/sdkMessage",
      "enabledBy": "_meta.claude.emitRawSDKMessages"
    },
    "outputFormat": {
      "scope": "session",
      "types": ["json_schema"],
      "config": "_meta.claude.options.outputFormat",
      "result": "usage_update._meta.claude.structuredOutput",
      "hiddenTool": "StructuredOutput",
      "rawEvents": "_claude/sdkMessage"
    },
    "goals": {
      "scope": "session",
      "state": "session_info_update._meta.claude.goal",
      "initialState": {
        "sessionResponses": [
          "session/new.result._meta.claude.goal",
          "session/load.result._meta.claude.goal",
          "session/resume.result._meta.claude.goal"
        ],
        "listSummary": "session/list.result.sessions[]._meta.claude.goal"
      },
      "setMethod": "_claude/session/setGoal",
      "semantics": "full-snapshot",
      "maxObjectiveBytes": 4096,
      "maxSummaryRunes": 256,
      "statuses": ["active", "completed", "blocked"],
      "clientSettableStatuses": ["active", "blocked"],
      "clearValue": null
    },
    "workflows": {
      "updates": true,
      "scope": "session",
      "toolKind": "think",
      "metadataPath": "tool_call_update._meta.claude.workflow",
      "logs": {
        "readByDefault": false
      },
      "rawEvents": "_claude/sdkMessage"
    }
  }
}
```

## Workflow metadata

Claude Code `Workflow` tool progress is exposed through normal ACP tool updates
with `_meta.claude.workflow` carrying the accumulated workflow state:

```json
{
  "claude": {
    "toolName": "Workflow",
    "workflow": {
      "taskId": "task-123",
      "workflowName": "review-plan",
      "status": "completed",
      "phases": [],
      "agents": [],
      "activeAgents": 0,
      "completedAgents": 1,
      "failedAgents": 0
    }
  }
}
```

See [Workflows](/docs/features/workflows) for status mapping, topology fields,
and log/privacy behavior.
