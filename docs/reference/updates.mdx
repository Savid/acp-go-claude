## Update mapping

During a prompt turn, Claude stream frames are translated into ACP session
updates:

| Update | Source |
| --- | --- |
| assistant message chunks | Claude assistant text |
| assistant image chunks | Claude assistant image results, one image per chunk |
| thought chunks | Claude thinking text |
| tool call | Claude tool start/input |
| tool result | Claude tool result |
| plan | Claude plan updates |
| available commands | Claude slash-command set (and refreshes) |
| usage | Claude usage counters (`_meta.claude.usage`) |
| session info | title and state changes |

## Assistant chunks are append-only and never repeated

Claude runs with partial messages enabled, so one assistant message arrives from
the harness twice: as the `stream_event` frames that carry it token by token, and
then as a terminal `assistant` frame restating the finished content. Only the
streamed frames become `agent_message_chunk` and `agent_thought_chunk` updates.
The terminal frame's text and thinking are dropped for exactly the message ids
the stream already delivered, so **concatenating every assistant chunk of a turn
reconstructs the assistant message once**, never twice.

This is a guarantee a host can build on: `agent_message_chunk` and
`agent_thought_chunk` are append-only deltas, never a snapshot, a repeat, or a
correction of text already sent in the same turn. Render a turn's assistant text
as the in-order concatenation of every chunk received and it is exactly right.

The suppression is evidence-based, not unconditional. An assistant message that
reached the adapter with no preceding stream frames — a non-streaming reply, and
every message replayed by `session/load` — is still emitted by its terminal
frame, once. A turn carrying several native assistant messages emits each of them
once, in native order, deduplicated on the native message identity rather than on
the text, so two messages that happen to say the same thing both arrive. Every
other block of a terminal frame is unaffected: its tool calls, tool results,
images, usage, stop reason, and `_meta.claude.messageId` identity are emitted
exactly as before.

The rule binds text content only. Agent images ride one chunk each, and
`tool_call_update.content` is a whole-array replacement by ACP definition.

## Related channels

- Raw Claude frames, when enabled, arrive separately on `_claude/rawEvent` and
  are **not** session updates — see [Raw events](/docs/features/raw-events).
- A turn *failure* is a JSON-RPC error on `session/prompt`, not an update — see
  the failure contract in [ACP methods](/docs/reference/acp-methods).
- Structured-output results are emitted on the turn's `usage_update` metadata
  under `_meta.claude.structuredOutput`, never on the prompt response.
- A terminal empty session-info notification and the successful prompt
  response carry the same durable transcript UUID under
  `_meta.claude.messageId`; load replay preserves the identity on the saved
  assistant update for native checkpoint reconciliation.
- Subagent output flattens into this same update stream, tagged with
  `_meta.claude.parentToolUseId`; untagged updates are the main agent — see
  [Metadata](/docs/reference/meta).
- A content-bearing tool update contains the complete current content array;
  clients replace the prior array. Status-only updates omit `content`.
